Replace the block-all-commitment logic in `pre_send_guard.py` with the D-26 §0 authorized/unauthorized test
by delegating to `authorize_offer` (built in 04-06). The guard now extracts the structured offer context
from the submit_reply payload (sub_type, template_code, offered thresholds, grounded eligibility,
asserts_mutation) and allows ONLY authorized in-policy templated offers (exit 0); everything else blocks

chokepoint contract.

highest-volume CS flow by blocking all refund/discount/replace language. The new guard distinguishes
policy-bounded templated offers (CORRECT, draft) from out-of-policy/fabricated commitments (block→escalate),
making the D-27 "0 UNAUTHORIZED commitments" gate achievable.
Output: reworked pre_send_guard.py + subprocess test proving exit 0 for authorized / exit 2 for each
unauthorized axis.
