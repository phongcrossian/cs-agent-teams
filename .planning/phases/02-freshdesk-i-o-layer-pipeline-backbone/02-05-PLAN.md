<objective>
Xây dựng hai đường nạp inbound vào queue — webhook (primary, low-latency) và reconciliation poller (backup) — slice thoả criterion #1 (inbound đến queued worker qua webhook + poller, xử lý exactly once). Cả hai feed cùng queue của plan 03; dedup tự động vì cùng idempotency key (D-02/D-09).

Mục đích: Hiện thực D-09 (webhook primary + reconciliation poller) với bảo mật webhook (HMAC-SHA256 custom secret header — Freshdesk không có HMAC native, RESEARCH A3) chống spoofing. **Design: RESOLVE-THEN-ENQUEUE (D-02).** Cả webhook receiver và poller đều gọi `GET /api/v2/tickets/{id}/conversations`, chọn latest inbound customer message (incoming=true, public — đây cũng là chỗ filter "là real inbound customer message không"), tính key `ticket_id:inbound_msg_id` thật, rồi enqueue. Vì cả hai path derive cùng key từ cùng ticket state → dedup tự động qua UNIQUE index (đúng rationale D-02). KHÔNG dùng sentinel `inbound_msg_id=0` và KHÔNG để worker re-key. (Webhook vẫn fetch conversations vì RESEARCH Pitfall 1 đã xác định body không có trong webhook payload — fetch là bắt buộc dù sao.)

Output: signature.verify, FastAPI receiver (verify → resolve → enqueue), shared `resolve_inbound_and_enqueue` helper, poller reconcile_once + loop cadence.
</objective>

DATA CONTRACT — Resolve-then-enqueue (D-02, dùng IDENTICAL ở cả webhook + poller):
  resolve_latest_inbound_msg_id(client, ticket_id) -> int | None:
    1. convs = await client.get_conversations(ticket_id)
    2. pick latest conversation có incoming=true AND private=false (real inbound customer message).
       Non-customer update (incoming=false, private=true) → return None → KHÔNG enqueue (loop-guard filter tại resolve step; định nghĩa "real inbound customer message").
    3. return conv.id của latest inbound (đây LÀ inbound_msg_id trong key).
  → key = compute_idempotency_key(ticket_id, inbound_msg_id) — webhook và poller tính RA CÙNG key từ CÙNG ticket state.
  → enqueue_ticket(conn, ticket_id, inbound_msg_id, payload); UNIQUE index trên idempotency_key → ON CONFLICT DO NOTHING là dedup guard duy nhất (không read-then-write race).

Webhook (RESEARCH § FastAPI Webhook Receiver):
  - Freshdesk KHÔNG có HMAC native (A3) → shared secret HMAC-SHA256 header X-Freshdesk-Signature; verify bằng hmac.compare_digest (constant-time) TRƯỚC mọi I/O.
  - payload chỉ cần ticket_id; webhook KHÔNG chứa conversation body (Pitfall 1) → resolve step fetch conversations (bắt buộc dù sao).
Poller (RESEARCH § Poller fallback D-09):
  GET /api/v2/tickets?updated_since={iso}&per_page=100 → mỗi ticket chạy CÙNG resolve_latest_inbound_msg_id → enqueue → ON CONFLICT auto-dedup với webhook path.
