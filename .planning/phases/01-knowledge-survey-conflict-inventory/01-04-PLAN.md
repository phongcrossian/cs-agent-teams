<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Historical Freshdesk tickets -> coverage validation | Tickets contain customer PII (names, emails, addresses, order IDs). This is the primary security threat of the phase. |
| Ticket sample -> git repo | Committing raw ticket samples would persist PII in version control permanently. |
| Ticket text -> LLM prompt (pairwise comparison) | Pasting raw customer data into an LLM prompt leaks PII to the model provider. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-PII-REPO | Information Disclosure | COVERAGE-MAP.csv and any committed ticket sample | mitigate | COVERAGE-MAP.csv stores category-level coverage only — no ticket bodies, names, emails, addresses, or order IDs. Raw ticket samples are NOT committed to the repo; the checkpoint asks for redacted/anonymized observations or category-level mappings only. Aligns with the project Presidio-redaction constraint. |
| T-01-04-PII-LLM | Information Disclosure | LLM-assisted pairwise conflict comparison | mitigate | The pairwise comparison operates on POLICY CLAIMS extracted from KB sources (Whimsical/Confluence/Templates), not on raw customer tickets. Any evidence-sample data fed to reasoning must be redacted first; do not paste raw customer ticket text into prompts beyond the minimal redacted snippet needed (D-06 + Presidio constraint). |
| T-01-04-PII-EXPORT | Information Disclosure | Human-provided Freshdesk sample | mitigate | Checkpoint instructs the human to redact PII before sharing or to provide category-level observations only. If a raw sample arrives, the executor must not commit it and must reduce it to category-level coverage facts. |
| T-01-04-SC | Tampering | Package installs | accept | Docs-only; no installs. |
